# Scenario SC-05 — Invitation fails if user is already a member

**Feature:** FE-02 · **Use case:** UC-06

## Summary
The room owner attempts to invite a user who is already a member of the room. The system must prevent the invitation and notify the owner.

## Given
- The user initiating the invite (the room owner) is authenticated.
- The room exists and the initiator is the owner.
- The invitee exists.
- The invitee is already present in the room's member list.

## When
- The room owner executes the room invitation action for the existing room member.

## Then
- The system identifies that the invitee is already a member.
- The invitation is rejected.
- The owner receives an error message indicating the user is already part of the room.

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Owner | Invites a user to the room | `server/server.go:201` |
| 2 | System | Validates owner, room existence, and invitee existence | `server/server.go:202-217` |
| 3 | System | Checks if invitee is already in `room_data.members` | `server/server.go:219` |
| 4 | System | Rejects invitation with error message | `server/server.go:221-222` |

## Related code and tests
- `server/server.go`: Implementation of `SendRoomInvite` with membership validation logic.

## Revision
- Initial draft: steps and assertions based on `server/server.go` implementation.

## Evidence index
- `server/server.go:219-223`: Membership validation logic which checks if `new_member.id` exists in `room_data.members` and returns an error if it does.

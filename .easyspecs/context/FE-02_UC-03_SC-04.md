# Scenario SC-04 — Deny update if maxSize is less than current members

**Feature:** FE-02 · **Use case:** UC-03

## Summary
The room owner cannot reduce the maximum capacity of a room to a value that is smaller than the current number of members in that room. If an attempt is made to do so, the system rejects the update and returns an error.

## Given
- The user is the owner of an existing room.
- The room has a current number of members.
- The user attempts to update the room settings, specifically the `max_size`.

## When
- The user provides a new `max_size` value via the `EditRoom` function.
- The provided `max_size` is greater than 0, and the number of current members (`len(r.members)`) is greater than the provided `max_size`.

## Then
- The system checks if `*maxSize > 0 && len(r.members) > *maxSize`.
- The system returns an error message: "Cannot set max size below current member count (X).", where X is the current member count.
- The `max_size` of the room remains unchanged.

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Owner | Calls `EditRoom` with a new `max_size` | `server/rooms.go:157` |
| 2 | System | Validates `max_size` against current member count | `server/rooms.go:172` |
| 3 | System | If `len(r.members) > maxSize`, returns error | `server/rooms.go:174-175` |

# Scenario SC-02 — Login with 'anonymous' nickname

**Feature:** FE-01 · **Use case:** UC-02

## Summary
Attempt to log in with the restricted nickname 'anonymous'. The system should reject this nickname and prompt the user to provide a valid one.

## Given
The client is connected to the server but not yet authenticated.

## When
The client sends a login command with the nickname "anonymous" (case-insensitive).

## Then
The server rejects the login attempt and re-prompts the client with the message "Nickname cannot be anonymous. Enter a valid nickname: ".

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Client | Sends login request with nick "anonymous" | - |
| 2 | Server (`handleLogin`) | Validates nick against "anonymous" | `server/handle_conn.go:174` |
| 3 | Server (`promptLogin`) | Sends re-prompt message | `server/handle_conn.go:175` |

# Scenario SC-03 — Fail to accept - already a member

**Feature:** FE-02 · **Use case:** UC-08

## Summary
The system prevents a user from accepting an invitation to a room they are already a member of. This avoids duplicate memberships and ensures room consistency.

## Given
- The user has an active invitation to join a specific room (e.g., `room_id`).
- The user is already present in the room's members list (`my_rooms[room_id]` exists).

## When
- The user calls `AcceptRoomInvite` for the `room_id` they are already a member of.

## Then
- An error message "You are already a part of this room" is sent to the user.
- The existing invitation for that room is removed from both the room's pending invites and the user's pending invites.
- The user is not joined to the room again (no redundant operations).

| Step | Actor / system | Expected | Evidence |

| 1 | User | Invokes `AcceptRoomInvite(room_id)` | `server/rooms.go:302` |

| 3 | System | Returns "You are already a part of this room" error | `server/rooms.go:311` |
| 4 | System | Removes the invite from room and user | `server/rooms.go:312-316` |

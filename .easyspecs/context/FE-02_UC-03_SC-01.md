# Scenario SC-01 — Successfully update room settings

**Feature:** FE-02 · **Use case:** UC-03

## Summary

The room owner successfully updates the room name and/or maximum allowed members.

## Given

- The user is authenticated and is the owner of the current room (`server/rooms.go:158`).
- The room exists.

## When

- The user initiates an update of the room settings (e.g., changing the room name or max size).
- The provided new name is unique or empty.
- If a new max size is provided, it must be non-negative and greater than or equal to the current member count (`server/rooms.go:167-176`).

## Then

- The room name and max size are updated (`server/rooms.go:177`, `server/rooms.go:189`).
- A success message with the updated payload is sent to the owner (`server/rooms.go:201`).

## Step-by-step

| Step | Actor / system | Expected | Evidence |

| 1 | Room owner | Initiates `EditRoom` request with new settings. | `server/rooms.go:157` |
| 2 | System | Validates ownership. | `server/rooms.go:158-161` |
| 3 | System | Validates new max size (if provided). | `server/rooms.go:166-176` |
| 4 | System | Updates max size (if valid). | `server/rooms.go:177` |
| 5 | System | Validates new room name (uniqueness). | `server/rooms.go:183-186` |
| 6 | System | Updates room name (if valid). | `server/rooms.go:189` |

# Use case IC-01 — CLI client main entry (Feature IN-01)

## Summary

The CLI client main entry point initializes the application, displays the bootstrap interface, establishes a secure TLS connection to the chat server, and transitions control to the session management system.

## Actors and stakeholders

- **CLI User:** The primary actor interacting with the chat client.
- **Server:** The remote entity the client connects to.

## Preconditions

- The client must be compiled and executed.
- The server must be accessible at `localhost:8080` (or via the `SERVER_URL` environment variable).

## Data inputs and validation

- **`SERVER_URL` (Environment variable):** Optional. If provided, overrides the default server address `localhost:8080`.
- **TLS Configuration:** `InsecureSkipVerify` is set to `true`, allowing connection to servers with self-signed certificates.

## Main flow (user- or operator-visible)

1.  User runs the binary.
2.  Application displays the bootstrap welcome message.
3.  Application attempts to connect to the configured server.
4.  If successful, application displays "Connected to server!".
5.  Application enters a CLI prompt loop for user commands.

## Code flow

### Request path (implementation)

1.  `main()` in `cmd/client/main.go` acts as the application entrypoint and calls `client.Connect()`.
2.  `client.Connect()` in `client/client.go` initiates the sequence:
    - Calls `printBootstrap()` from `client/help.go`.
    - Determines `serverUrl` (env var or default).
    - Attempts `tls.Dial` with `InsecureSkipVerify: true`.
    - On failure, prints an error and terminates.
    - On success, initializes `readline` and starts the command loop via `runSession()`.

## Alternate flows

- **Connection Failure:** If `tls.Dial` fails, the application informs the user and terminates immediately.

## Postconditions

- A secure TLS connection is established and maintained until termination.
- A command session is active and awaiting user input.

## Errors and edge cases

- **Server Down:** Handled via error check on `tls.Dial`, resulting in an error message and graceful exit.
- **Invalid `SERVER_URL`:** `tls.Dial` will return an error if the URL is unreachable or invalid.

## Technical mapping

- **Bootstrap/Help:** `client/help.go` handles UI components like `printBootstrap()` and `printClientHelp()`.

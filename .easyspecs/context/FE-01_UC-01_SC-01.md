# Scenario SC-01 — Successful login with valid nickname

**Feature:** FE-01 · **Use case:** UC-01

## Summary
The user successfully authenticates by providing a valid, unique nickname.

## Given
The client connection is established, and the client is not yet authenticated.

## When
The client sends a message that triggers `handleLogin` with a valid, non-empty, unique nickname (i.e., not 'anonymous' and not already taken by another connected user).

## Then
1. The client's `authenticated` flag is set to `true`.
2. The client's `nick` field is updated with the provided nickname.
3. A confirmation message (`DONE`) is sent to the client.
4. A `CREATE_FILE_PORT` message is sent to the client to initialize file transfer capability.

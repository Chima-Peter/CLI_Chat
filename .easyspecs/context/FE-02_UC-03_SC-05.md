# Scenario SC-05 — Deny update if room name is taken

**Feature:** FE-02 · **Use case:** UC-03

## Summary
The system prevents a room owner from renaming their room to a name that is already assigned to another existing room, ensuring room name uniqueness within the system.

## Given
- An existing room exists with a specific name (e.g., "RoomA").
- A user owns another room ("RoomB").

## When
- The owner of "RoomB" attempts to rename their room to "RoomA".

## Then
- The server checks if "RoomA" is already taken by another room.
- The server rejects the rename request.
- The client receives an error message: "Room name RoomA is already in use."
- The room "RoomB" retains its original name.

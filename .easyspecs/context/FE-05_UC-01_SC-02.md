# Scenario SC-02 — Attempt to block an already blocked user

**Feature:** FE-05 · **Use case:** UC-01

## Summary
The user attempts to block another user who is already on their block list. The system should identify the user is already blocked and return an error message to the user, preventing the blocking operation from proceeding redundantly.

## Given
The user is logged in, and the target user is already in the blocker's `blocked_users` map.

## When
The blocker issues a request to block the target user.

## Then
The system verifies if the target user is in the `blocked_users` list and returns an error message: `"<target.nick> is already blocked."`.

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Blocker | Request to block target user | `server/client.go:323` |
| 2 | System | Checks if user is already blocked | `server/client.go:330` |
| 3 | System | Returns error "is already blocked" | `server/client.go:332` |

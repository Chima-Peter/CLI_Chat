# Scenario SC-04 — Attempt to log in with 'anonymous' nickname

**Feature:** FE-01 · **Use case:** UC-01

## Summary

This scenario covers the attempt to log in using the reserved nickname "anonymous". The system explicitly disallows this nickname.

## Given

- The client is not authenticated.
- The user provides "anonymous" (or any case-insensitive variation thereof) as a nickname during the login process.

## When

- The system processes the login request in `handleLogin`.
- `strings.EqualFold` is used to compare the provided nickname with "anonymous".

## Then

- The login attempt is rejected.
- The user receives a message: "Nickname cannot be anonymous. Enter a valid nickname: ".
- The client remains in an unauthenticated state.

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | User | Provides "anonymous" as nickname | `server/handle_conn.go:164` |

| 3 | System | Rejects login, prompts for new nickname | `server/handle_conn.go:175-176` |

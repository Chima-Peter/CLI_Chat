# Use case IC-03 — Construct TLS configuration (Feature IN-03)

## Summary

This infrastructure component constructs a `tls.Config` object using the previously generated TLS certificate and private key, preparing them for use in TLS-encrypted network communication within the application.

## Actors and stakeholders

- **Developer / Application:** The component is intended for use in a development environment to provide TLS capabilities.

## Preconditions

- A valid PEM-encoded TLS certificate and RSA private key must have been generated and available in memory (typically prepared by preceding components IC-01 and IC-02).

## Data inputs and validation

- **Inputs:** `certPEM` (byte slice), `keyPEM` (byte slice).
- **Validation:** `tls.X509KeyPair(certPEM, keyPEM)` validates that the certificate and key are correctly formatted and form a valid pair.
- **Failure behaviour:** If `tls.X509KeyPair` fails to parse the pair, the function returns a nil `*tls.Config` and a wrapped error: `"could not load TLS certificate: %w"`.

## Main flow (user- or operator-visible)

1. The component receives the PEM-encoded certificate and private key.
2. It calls `tls.X509KeyPair` to parse and load the certificate pair.
3. It initializes and returns a `tls.Config` object containing the loaded certificate.

## Code flow

1. **Load Key Pair:** `tls_config/config.go:41` uses `tls.X509KeyPair` with `certPEM` and `keyPEM`.
2. **Error Handling:** `tls_config/config.go:42-44` handles potential errors during parsing, returning a wrapped error.
3. **Return Config:** `tls_config/config.go:46` returns a new `&tls.Config{Certificates: []tls.Certificate{cert}}`.

## Alternate flows

- **Error Path:** If the provided PEM data is invalid, `tls.X509KeyPair` fails, and the function terminates early, returning the error to the caller.

## Postconditions

- A `*tls.Config` object is successfully created and returned, ready to be used in setting up a TLS server or client.

## Errors and edge cases

- **Invalid certificate/key:** If the provided bytes do not constitute a valid X509 key pair, the function returns an error.

## Technical mapping

- `tls.X509KeyPair`: Standard Go `crypto/tls` function used to parse and load the pair.

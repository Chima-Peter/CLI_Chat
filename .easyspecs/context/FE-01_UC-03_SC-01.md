# Scenario SC-01 — Log out while unauthenticated

**Feature:** FE-01 · **Use case:** UC-03

## Summary
The user attempts to log out before they have successfully authenticated. The system handles this by closing the connection immediately.

## Given
The user has connected to the server but has not yet provided a nickname or completed the login process (`cl.authenticated == false`).

## When
The user sends a `LOGOUT` action request to the server.

## Then
The server's `dispatchMessage` function detects the `LOGOUT` action for an unauthenticated user and returns `true`, which triggers the closing of the connection in the `HandleConn` loop.

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Client | Sends `LOGOUT` action while unauthenticated | `server/handle_conn.go:65-66` |
| 2 | Server (`dispatchMessage`) | Receives `LOGOUT` and returns `true` | `server/handle_conn.go:65-66` |
| 3 | Server (`HandleConn`) | Receives `true`, returns from the connection loop | `server/handle_conn.go:52-53` |
| 4 | Server (`HandleConn`) | Connection closes via `defer conn.Close()` | `server/handle_conn.go:15` |

## Related code and tests
- `server/handle_conn.go`: Contains the `HandleConn` function and `dispatchMessage` logic.

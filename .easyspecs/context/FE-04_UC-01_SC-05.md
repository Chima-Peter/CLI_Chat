# Scenario SC-05 — Attempt switch with missing context name

**Feature:** FE-04 · **Use case:** UC-01

## Summary

The user attempts to switch the current context (e.g., room or friend) without providing the required context name. The system validates that the name is provided and returns a usage error message if it is missing.

## Given

- The client is connected to the server.
- The user initiates a `/switch` command with a context type but without providing a context name.

## When

- The user sends a message or invokes the `/switch` command with missing name parameter.
- The server calls `SwitchContext` handler.

## Then

- The server checks if the provided `name` string is empty.
- An error message indicating the correct usage is sent to the client.
- The context switch is aborted.

## Step-by-step

| Step | Actor / system | Expected | Evidence |

| 1 | User | Initiates command | N/A |
| 2 | System | `SwitchContext` receives empty `name` | `server/server.go:303` |
| 3 | System | Validates `name == ""` | `server/server.go:304` |
| 4 | System | Returns usage error `cl.err` | `server/server.go:305` |
| 5 | System | Aborts processing | `server/server.go:306` |

## Related code and tests

- `server/server.go` implements the `SwitchContext` function and handles the input validation.

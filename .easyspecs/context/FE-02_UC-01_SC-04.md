# Scenario SC-04 — Try to join another room while already a member

**Feature:** FE-02 · **Use case:** UC-01

## Summary

The user attempts to join a room they are already a member of, while they are currently active in a different room. The system handles this by sending a welcome message for their current room.

## Given

- The user is already a member of the target room `r`.
- The user is currently active in a different room (`cl.room`).
- `cl.room` is not `nil`.

## When

- The user invokes `JoinRoom` for the target room `r`.

## Then

- The system identifies that the user is already a member of `r`.
- The system sends a welcome message for the user's *current* room (`cl.room`) instead of joining `r` (or performing another action).

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Client | User calls `JoinRoom` for room `r`. | `server/rooms.go:76` |
| 2 | System | Checks if user is already a member of `r`. | `server/rooms.go:78` |
| 3 | System | Checks if user is already in a room and if they are a member of `r`. | `server/rooms.go:82-88` |
| 4 | System | Sends a welcome message for the current room `cl.room`. | `server/rooms.go:89` |

# Scenario SC-04 — Attempt to block with invalid nickname format

**Feature:** FE-05 · **Use case:** UC-01

## Summary
The user attempts to block another user by providing an invalid nickname (either empty or containing spaces). The client-side logic enforces nickname formatting rules before sending a request to the server, resulting in an immediate local error.

## Given
The user is logged in to the chat application and has the command line interface ready to accept input.

## When
The user inputs a command in the format `/user/block <invalid_nickname>`, where the nickname is empty or contains whitespace characters (e.g., `/user/block " "` or `/user/block `).

## Then
The client application identifies the invalid nickname format via `requireName` validation and displays an error message to the user: "usage: /user/block <user>: names cannot contain spaces" or "usage: /user/block <user>: name cannot be empty". No network message is sent to the server.

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | User | Enters `/user/block` with an invalid nickname. | `client/message.go:397-404` |
| 2 | System | Executes `requireName` to validate the nickname. | `client/message.go:96-104` |
| 3 | System | Detects invalid nickname (empty or spaces). | `client/message.go:97-102` |
| 4 | System | Returns an error preventing command execution. | `client/message.go:398-399` |

## Related code and tests
The validation logic resides in `client/message.go`, specifically `requireName` which is used by `buildCommandMessage` for the `/user/block` command.

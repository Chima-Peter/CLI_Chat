# Scenario SC-03 — Deny update if maxSize is negative

**Feature:** FE-02 · **Use case:** UC-03

## Summary

This scenario covers the validation logic where a room owner attempts to update a room's settings with a negative `maxSize`. The system must reject this update and return an appropriate error message.

## Given

- A room exists.
- The user is the owner of the room.

## When

- The room owner submits an update request for the room.
- The `maxSize` field in the request is set to a negative value.

## Then

- The system detects the invalid `maxSize`.
- The system returns an error: "Max size cannot be negative."
- The room settings remain unchanged.

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Owner | Sends update request with negative `maxSize` | - |
| 2 | System | Checks if `maxSize` is negative | `server/rooms.go:167` |
| 3 | System | Returns error "Max size cannot be negative." | `server/rooms.go:169` |

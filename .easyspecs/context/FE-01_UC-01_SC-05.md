# Scenario SC-05 — Attempt to log in with a nickname already taken

**Feature:** FE-01 · **Use case:** UC-01

## Summary
User tries to log in with a nickname that is already in use by another connected client. The server detects the collision and prompts the user to choose a different nickname.

## Given
A user is attempting to login (`server/handle_conn.go:63`) while another user is already logged in with the same nickname.

## When
The user sends a `LOGIN` action with the taken nickname (`server/handle_conn.go:178`).

## Then
The server detects that the nickname is taken (`server/utils.go:116-126`) and prompts the user to enter a different nickname (`server/handle_conn.go:179`).

# Scenario SC-01 — Owner successfully deletes the room

**Feature:** FE-02 · **Use case:** UC-05

## Summary
The room owner initiates the deletion of a room. The system validates ownership, notifies all current members of the deletion, removes the room from the server and all client-side tracking.

## Given
- The user requesting the deletion is a member of the room (`server/rooms.go:217-220`).
- The user requesting the deletion is the owner of the room (`server/rooms.go:222-224`).

## When
- The user triggers the `DeleteRoom` action (`server/rooms.go:216`).

## Then
- All room members have the room removed from their `my_rooms` and `room_invites` lists (`server/rooms.go:232-233`).
- If a member was currently in the deleted room, they are detached from it (`server/rooms.go:234-236`).
- All members are notified of the room deletion (`server/rooms.go:237-239`).
- The room is removed from the server's registry (`server/rooms.go:243-245`).
- The owner receives a confirmation message (`server/rooms.go:247`).

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | System | Validate user membership | `server/rooms.go:217-220` |
| 2 | System | Validate user ownership | `server/rooms.go:222-224` |
| 3 | System | Iterate through all members and remove access | `server/rooms.go:231-240` |
| 4 | System | Remove room from server registry | `server/rooms.go:243-245` |
| 5 | System | Confirm deletion to owner | `server/rooms.go:247` |

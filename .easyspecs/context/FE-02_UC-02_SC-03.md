# Scenario SC-03 — Join private room without password fails

**Feature:** FE-02 · **Use case:** UC-02

## Summary

When a user attempts to join a room that has been configured as private (requiring a password), the system detects the room's private status and prompts the user to provide a password, instead of allowing them to join the room directly.

## Given

- A room `r` exists and is configured as a private room (`is_private` is true).

## When

- The user (client `cl`) initiates a request to join the room by calling `r.JoinRoom(cl)`.

## Then

- The `JoinRoom` method detects that `is_private` is true.
- The system sends a `GET_ROOM_PASSWORD` message to the client, requesting the room password.
- The `JoinRoom` method exits, and the user is not added to the room's members list at this stage.

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Client `cl` | Calls `r.JoinRoom(cl)` | `server/rooms.go:76` |
| 2 | Room `r` | Checks `r.is_private` | `server/rooms.go:99` |
| 3 | Room `r` | Sends `GET_ROOM_PASSWORD` to client | `server/rooms.go:100-103` |
| 4 | Room `r` | Exits without joining | `server/rooms.go:104` |

## Related code and tests

- `server/rooms.go`: Contains the `JoinRoom` logic that handles private room password requirement.

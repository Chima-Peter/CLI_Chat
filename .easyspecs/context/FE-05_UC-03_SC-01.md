# Scenario SC-01 — Check status of unblocked offline user

**Feature:** FE-05 · **Use case:** UC-03

## Summary
The system reports the status of a user. In this scenario, the target user is not in the requester's block list, and the user is currently offline.

## Given
- The requester (`cl`) is authenticated.
- The target user (`target`) is not in the requester's block list (`cl.blocked_users`).
- The target user's `online` attribute is `false`.

## When
- The requester calls `GetUserStatus(target)`.

## Then
- The system determines the user is "offline".
- The system constructs a message with `online: false`, `blocked: false`, and an appropriate status string (`<nick> is offline.`), then sends it to the requester via `send_user_message`.

## Step-by-step

| Step | Actor / system | Expected | Evidence |
| --- | --- | --- | --- |
| 1 | Requester | Calls `cl.GetUserStatus(target)` | `server/client.go:366` |
| 2 | System | Checks if target is in block list (`isBlocked = false`) | `server/client.go:368` |
| 3 | System | Reads target's online status (`online = false`) | `server/client.go:372` |
| 4 | System | Sets status string to "offline" | `server/client.go:381-383` |
| 5 | System | Sends status message to requester | `server/client.go:386-393` |

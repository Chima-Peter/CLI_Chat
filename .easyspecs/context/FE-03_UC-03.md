# Use case UC-03 — Reject friend request (Feature FE-03)

## Summary

The actor rejects a pending friend request from another user. This operation removes the friend request from the actor's pending requests and the target user's sent requests, notifying both users of the action.

## Actors and stakeholders

- **Actor**: A user who has received a pending friend request.
- **Target**: The user who originally sent the friend request.

## Preconditions

- The actor must be authenticated.
- A pending friend request must exist from the Target to the Actor.

## Data inputs and validation

- **`targetID`** or **`targetName`**: Used to identify the target user.
- **Validation**:
  - The system resolves the user via `s.resolveUser(targetID, targetName)` (`server/server.go:595`).
  - If the user cannot be resolved, an error is returned (`server/server.go:596-598`).
  - The system verifies the existence of the pending request in the actor's pending list (`server/client.go:169`) and the target's sent list (`server/client.go:177`).
  - If either is missing, an error is returned (`server/client.go:172,180`).

## Main flow (user- or operator-visible)

1. The actor initiates the rejection of a friend request by providing the target's ID or nickname.
2. The system verifies the user and the existence of the pending friend request.
3. The system removes the request from the actor's pending friend requests.
4. The system removes the request from the target's sent friend requests.
5. The system notifies both the actor and the target user.

## Code flow

1. **Entrypoint**: `server.RejectFriendRequest` receives `targetID` and `targetName` (`server/server.go:594`).
2. **User Resolution**: `s.resolveUser` retrieves the `client` object for the target (`server/server.go:595`).
3. **Core Logic & Persistence**: `cl.RejectFriendRequest(target)` is called, which:
   - Verifies existence of request in `cl.pending_friend_requests` (`server/client.go:169`).
   - Verifies existence of request in `friend.sent_friend_request` (`server/client.go:177`).
   - Deletes entries from both maps (`server/client.go:185,189`).
4. **Notification**: Both users receive a message indicating the request was rejected (`server/client.go:192-193`).

## Alternate flows

- **User not found**: If `targetID`/`targetName` does not match an active client, an error is returned.
- **Request not found**: If the friend request does not exist, an error is returned.

## Postconditions

- The friend request is removed from both the actor's and the target user's records.

## Errors and edge cases

- **Target user not found**: `s.resolveUser` returns an error, preventing the rejection.
- **Request missing**: If the request was already accepted, rejected, or canceled, the system returns an error.
